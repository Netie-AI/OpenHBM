The open HBM4 and LPU master plan
An open-source HBM4 controller, PHY-shim, and RISC-V-native LPU accelerator is achievable as a 24-month community project — not as silicon that beats Rubin, but as the royalty-free JEDEC-compliant reference stack that Malaysian, ASEAN, Chinese, Indian, and second-tier hyperscaler customers adopt because they have no alternative that escapes NVIDIA+SK Hynix lock-in. The realistic moat is trademark-enforced compatibility (the RISC-V playbook), not silicon supremacy. The core technical bet: treat HBM4 as a compiler-managed streaming tier at 8–26 TB/s per chip (the opposite of Groq's SRAM-only doctrine), wrapped by an open Apache-2.0 controller on top of LiteDRAM's scheduler and pulp-platform's AXI fabric, feeding a Tenstorrent-style tiled dataflow fabric composed of PULP RedMulE systolic engines and open FlashAttention HLS blocks. HBM4 base-die silicon is a Phase-3 stretch; the controller+PHY-shim+LPU reference design, verified in simulation and emulated on a used Alveo U280 via the AMD HACC cluster, is the Phase-1 deliverable. Everything below is a synthesized plan for executing that through 2028 from Malaysia, using AI coding agents, open infrastructure, and a lean funding stack starting with NLnet (€50k) → MDEC MDAG (RM5M) → IC Design Park 2 Cyberjaya (free EDA) → Sovereign Tech Fund (€1M) → Khazanah Dana Impak (RM5–20M).

1. Product requirements document (PRD)
Project codename: Netie Open HBM (working name; reserve trademark). Positioning tagline: "The RISC-V of memory and AI accelerators."
Mission statement. Deliver a JEDEC JESD270-4A–compliant, royalty-free HBM4 memory subsystem (controller + PHY-shim + DFT + RAS + security wrapper) tightly coupled to an open RISC-V-native LPU accelerator optimized for LLM inference and MoE workloads. All RTL Apache-2.0 (analog/GDSII under CERN-OHL-W-2.0). Trademark-controlled compatibility certification. Vendor-neutral by construction.
Primary personas.
•	Sovereign AI builder (Malaysia, Singapore, UAE, India, Korea-ex-Samsung-SK, China-ex-NVIDIA) who needs AI silicon outside the CUDA/NVLink/SK-Hynix-base-die stack.
•	ASEAN/European semiconductor startup seeking controller IP without million-dollar Synopsys/Cadence HBM4 licenses.
•	Academic/research group needing a reference HBM4 design to extend (rowhammer defenses, ECC, PIM, address mapping research).
•	Hyperscaler custom-silicon team looking for a royalty-free base controller to save IP NRE before building differentiated logic into their custom HBM4E base die.
Functional requirements (MoSCoW).
Must: JESD270-4A-compliant command/data/refresh FSMs across 32 channels × 2 pseudo-channels; AXI4 multi-port front-end and APB CSR; DFI-compatible PHY boundary; programmable XOR address-mapping policy; DRFM + RFM row-hammer mitigation; link ECC (SEC-DED minimum, chipkill target); PASR/self-refresh; IEEE 1500 + IJTAG DFT wrapper; cycle-accurate HBM4 behavioral model for sim (extended DRAMsim3); cocotb UVM-style verification suite with coverage; open LPU reference of ≥16 tiles, each with a RedMulE-style FP16/FP8 systolic (32×32 MACs), SFPU vector unit, 1.5 MB L1, five RISC-V "baby" cores (unpack/math/pack/2× data-move); mesh NoC (PULP or ESP); Ethernet scale-out; TVM+VTA compiler backend; complete Sphinx/MkDocs docs.
Should: TileLink-C front-end option; formal proofs of channel non-interference and refresh correctness; open FlashAttention HLS block (arXiv 2505.14314) per tile cluster; AES-GCM line-rate memory integrity (OpenTitan primitive); UCIe adapter for chiplet seam; Linux SMP on a CVA6 "big" control core; Google SparseCore-style gather/scatter engine for MoE/embedding.
Could: CXL 3.x type-2 attach for memory pooling; PIM primitives in base-die conceptual model; optical-ICI-equivalent via Ethernet/silicon-photonics stub (A*STAR IME partnership).
Won't (v1): Actual HBM4 base die tapeout at TSMC N12FFC+/N5 (stretch to Phase 3, budget $20M+); CoWoS packaging; custom DRAM cell development; anything requiring non-JEDEC PHY electrical characterization.
Non-functional targets.
•	Verification confidence: 95%+ functional coverage on controller; all assertions formally proved on sub-blocks ≤10 k gates (SymbiYosys); mutation-coverage ≥80% on agent-authored modules (mcy).
•	FPGA prototype: synthesizable on Alveo U280/U55C/VCK5000; HBM2 hardened IP used as PHY-shim backstop.
•	ASIC PPA baseline: Yosys+OpenROAD elaboration on SkyWater 130 (peripheral logic) and IHP SG13G2 (mixed-signal PHY experiments); commercial Innovus/DC for 28nm–16nm shuttle tapeouts via Europractice.
•	License posture: Apache-2.0 RTL, CERN-OHL-W-2.0 PHY/analog, CC-BY-4.0 docs; trademark-controlled Netie Open HBM Compatible™.
Critical assumptions and dependencies. JEDEC JESD270-4A public PDF available via free JEDEC registration (not redistributable — clean-room summary maintained in repo); DRAMsim3 can be extended for HBM4 timing; AMD HACC cluster access granted via university affiliate; NLnet grant awarded on 2026 Q3 round; no adversarial patent assertion in the first 18 months (mitigated by OIN membership and early arXiv publication).

2. Repository and file structure
A single monorepo (netie-open-hbm) organized after OpenTitan's battle-tested pattern, with FuseSoC CAPI2 .core files per IP for Chipyard/LiteX/ESP interoperability and SiliconCompiler Python-native flows for ASIC orchestration. Top-level directories: docs/ (Sphinx + MkDocs + Asciidoctor spec), hw/ip/ (leaf IP: hbm4_ctrl, hbm4_phy_shim, ecc, refresh_mgr, addr_map, cdc, mbist_wrapper, accel_core, prim_generic), hw/subsystems/ (mem_ss, compute_ss, io_ss), hw/top/ (chiplet and monolithic variants), hw/vendor/ (pinned third-party: lowrisc_prim, opentitan_regtool, pulp_common_cells via util/vendor.py), hw/vip/ (cocotb-based JESD270-4 behavioral model, AXI and DFI VIP), hw/formal/ (cross-module SVA library), fpga/ (Alveo U280/U55C, VCU128, VCK5000 targets), syn/ (Yosys + Design Compiler scripts), pd/ (ORFS on SkyWater/IHP and Innovus templates for N16/N28 sign-off), sw/ (TVM backend, drivers, firmware, benchmarks), sim/ (cocotb runners, Makefiles), ci/ (GitHub Actions reusable workflows), scripts/, util/reggen|testplanner|dvsim, third_party/. A root CLAUDE.md defines the SystemVerilog subset, banned constructs, clock-domain conventions, and primitive library so agents stay in bounds. flake.nix and a devcontainer.json pin the OSS CAD Suite 2026-04-07 nightly for reproducibility. Every IP directory mirrors OpenTitan's {rtl, dv, fpv, data, doc, syn, lint} layout plus an <ip>.core FuseSoC manifest.

The project splits into four phases over 36 months. Each phase ends with a tangible release, a public demo, and a funding milestone.
Phase 0 — founder ramp and public commitment (months 0–3)
Goal: establish the public project, secure the first grant, lock the technical foundations. Register the Malaysian Sdn Bhd; file trademarks for the project name and compatibility mark in MY/SG/US/EU; open the GitHub organisation with Apache-2.0 license, DCO bot, and a CLAUDE.md style guide. Apply to Open Invention Network under the free small-organisation tier, RISC-V International community membership (free), CHIPS Alliance associate tier (free for non-profits), OpenHW Group, and UCIe Adopter. Apply for Malaysia Digital (MD) status via MDEC. Submit an NLnet NGI0 Commons Fund application (€50k target) for "open HBM4 controller RTL v0.1 and behavioural model" by the April 1, 2026 deadline (already passed — target October 1, 2026 round). Submit AMD HACC application through NUS Singapore for free Alveo U280/U55C cluster access. Publish a first public design document on arXiv ("Towards an Open, JEDEC-Compliant HBM4 Controller and RISC-V-Native LPU") to stake prior-art claims and attract contributors. Spin up the project Discord/Matrix and a monthly technical call. Deliverables: public repo skeleton, design document v0.1, three initial agent-orchestrated modules (clean-room HBM4 timing table summariser from JESD270-4A, DRAMsim3 timing-parameter patch, LiteDRAM fork with litedram/phy/hbm4/ stub).
Phase 1 — simulation-first controller and LPU MVP (months 3–15)
Goal: a complete, verified, simulation-grade HBM4 controller + 4-tile LPU, runnable entirely on a laptop with Verilator and cocotb. This is the Phase where AI coding agents do the vast majority of the work under human review. The controller is forked from LiteDRAM (BSD-2-Clause), with LiteDRAM's scheduler, bank-machine, and refresh architecture retained and the PHY boundary reworked to HBM4's 32-channel × 2-pseudo-channel × 2048-bit DFI. The accelerator is composed of PULP RedMulE (FP16/FP8 systolic, SolderPad 0.51) as the MatMul engine, PULP NEureka for quantized ops, ESP (Columbia) as the SoC framework carrying the NoC and memory tile, a Gemmini-style scratchpad/accumulator pattern, and an adaptation of the open FlashAttention HLS block from arXiv 2505.14314. Control plane is CVA6 (OpenHW, Apache + Solderpad). Interconnect is TileLink-C on the coherent side, pulp-platform/axi on the HBM4 front-end, and APB for CSRs. Security plumbing (OTP, keymgr, lifecycle, alert handler, AES-GCM) is vendored from OpenTitan.
Verification uses Verilator 5.046/5.047 + cocotb 2.0.1 + pyuvm 4.0.1 + cocotb-coverage, with SymbiYosys bounded model check on the scheduler, refresh manager, ECC, and address-map submodules, EqY for agent refactor equivalence, and mcy mutation coverage as a required CI gate for any module authored by an agent. The behavioural HBM4 memory model is an extended DRAMsim3 compiled against cocotb via DPI — because no open JESD270-4 BFM exists, this extension is the project's single most-valuable early upstream contribution. An ci/ reusable GitHub Actions workflow runs Verible linting, Verilator builds, cocotb regression matrix (Verilator + Icarus), SymbiYosys formal, and an nightly Vivado bitstream for the Alveo U55C target. Milestones: M1 (month 6) controller FSM + DRAMsim3 integration passes directed tests; M2 (month 9) 4-tile LPU with RedMulE and an attention block runs BERT-Base inference in simulation; M3 (month 12) full coverage-driven regression green on 32-channel controller; M4 (month 15) on-Alveo U55C emulation at reduced data rate via HACC, a demo running Llama-3.2-1B through the open stack with performance numbers published at FOSDEM 2027, ORConf 2027, and arXiv.
Phase 2 — first open-silicon tapeouts and community expansion (months 15–27)
Goal: transform from a simulation project into a silicon-validated open project with real contributors. The project becomes a CHIPS Alliance Technical Project to gain the patent-grant umbrella (OWFa 0.9) and Linux Foundation governance, while retaining its own trademark-enforced compatibility program modeled on RISC-V International's CSC. Membership tiers modeled on OpenTitan (Platinum/Gold/Silver/Bronze). Establish a Technical Steering Committee of three to five members with a public RFC process and gate reviews borrowed from the OpenHW model (Concept → Launch → Plan → RTL Freeze).
Silicon side: submit two Tiny Tapeout tiles on SkyWater SKY130 (TTSKY26b) and IHP SG13G2 (TTIHP26a) for €70–150 each — the peripheral logic (CSR/APB bridge, a minimal AI MAC) — mostly as a community rite of passage and silicon-first proof. Then a SkyWater SKY130 chipIgnite/ChipFoundry block (~$12k, July 2026 delivery) carrying a small address-mapping test block and one RedMulE tile. In parallel, apply through USM-CEDEC to SilTerra (180/130 nm Malaysia, MYR 30–80k) for a PMIC/interface test chip aligned with NSS narrative. Apply to Europractice IHP SG13G2 (130 nm BiCMOS, 350 GHz SiGe HBT — useful for PHY equaliser experiments) and GF 22FDX mini@sic standard non-EU academic rate (~€15–25k/mm²) for a 1-mm² first FinFET-class digital tile carrying a 1–4 channel reduced-rate HBM-PHY experiment using commercial-licensed Cadence/Synopsys HBM PHY IP under their University programs.
Funding side: MDEC MDAG (up to RM5M, 3-year), Selangor/Ehsan Capital (part of the RM100M fund), Khazanah Dana Impak/Cambrian (RM5–20M seed), A*STAR IME partnership via EDA Garage. On the Western side: Sovereign Tech Fund (€200k–€1M for maintenance infrastructure once the project is demonstrably shipping), and a second NLnet round for specific deliverables. Community milestones: public Hot Chips 2027 tutorial; ASPLOS paper on the HBM4 address-mapping policy; dedicated track at RISC-V Summit Asia (Kuala Lumpur or Singapore); first external contributors via CREST-funded MSc/PhD theses at UM, USM, UTM, NUS. End-Phase-2 deliverables: v1.0 controller and LPU release with compatibility test suite; first silicon chiplet tapeout demonstrated; ≥3 corporate sponsors; paper trail at ≥4 peer-reviewed venues.
Phase 3 — meaningful silicon on an advanced node (months 27–42)
Goal: a real AI-accelerator chiplet on TSMC N16FFC or N7, UCIe-compliant, that third parties can tape out unchanged. Europractice TSMC N16 (~€25–30k/mm², five shuttles/year) hosts a 10–50 mm² UCIe chiplet running the LPU fabric at ~1 TOPS INT8 per mm². In parallel, an HBM3-class PHY test chip on N7 (April 2026 Europractice run reappears annually, €650–900k for a small die) validates the controller + open PHY adapter against real HBM3/3E DRAM modules. Advanced packaging is out-of-reach for CoWoS, but ASE Malaysia (Penang) organic-substrate flip-chip + a simple chiplet bridge is negotiable — the physical co-location with CREST, USM-CEDEC, and MSIA makes this the single most leverageable Malaysian advantage. Partnerships: formal MOU with A*STAR IME (Singapore) on packaging research; TSRI Taiwan via USM/UM university partnership; apply to Intel Foundry Shuttle 16 as "select customer" (Intel is openly recruiting). Funding: by this phase, MSIA/MITI NSS strategic allocation (one of the explicit NSS pillars is the RM1.59B Advanced Packaging Centre — directly aligned), plus seed or Series A from Khazanah/Ehsan. Headcount grows to ten to fifteen. Project is now a Linux Foundation directed fund with ≥5 Platinum sponsors and paid infrastructure staff, modeled structurally on CHIPS Alliance.
Phase 4 (stretch, months 42+) — the open HBM4 base die
This phase is explicitly aspirational and gated on $20M+ funding. Only realistic once the Phase-3 LPU chiplet has external adopters. Two plausible paths: (a) open HBM4 PHY test chip at TSMC N5 via CyberShuttle, $20M+, using the Phase-2 PHY adapter IP matured into full signal-integrity sign-off on Ansys/Cadence Clarity (commercial required — openEMS/Xyce are simply not enough at 10+ Gbps across 2048 lanes); (b) partnership with SK Hynix Open Collaboration or Samsung Custom HBM team as a customer designing into a commercial base die. The fundamental reality confirmed by subagent research: no open PDK exists at the logic nodes (N12FFC+, N5, N3) that HBM4 base dies require; the CoWoS-S/L interposer supply through 2027 is ~85% locked by NVIDIA/Broadcom/Google/AMD; and even Samsung's custom HBM program is sized for hyperscalers, not startups. This phase is the 5–7-year horizon, not the 3-year. The honest strategic framing: by Phase 4, the project's moat is compatibility certification and adoption, not bespoke base-die silicon.

4. Agent prompts per module
Each major module in hw/ip/ gets a dedicated agent prompt stored in docs/agent-prompts/. The pattern borrows from the spec-anchored knowledge-graph approach (VeriGraphi) and interface-first scaffolding. A shared preamble reads:
You are working inside the netie-open-hbm monorepo. Read CLAUDE.md for allowed SystemVerilog subset, banned constructs, clock-domain conventions, and the primitive library (lowrisc_prim, pulp_common_cells). All code must be Apache-2.0, lint-clean under verible-verilog-lint --rules-config=.rules.verible_lint, elaborate cleanly in Verilator 5.046 with -Wall -Wpedantic --timing, and pass yosys -p 'hierarchy -check'. Before writing implementation, produce (1) a port/parameter table, (2) a cycle-by-cycle timing narrative in comments, (3) SVA assertions for every protocol invariant. Then implement. After implementation, write a cocotb testbench with a Python golden reference model in dv/env/ and directed + pyvsc-constrained-random tests. Never sample signals across clock domains without prim_sync_2flop or prim_fifo_async. All CSRs must be declared in Hjson and generated via util/reggen/regtool.py.
Module-specific prompt stubs include: hbm4_ctrl ("Implement the JESD270-4A command and data FSMs across 32 independent channels and 2 pseudo-channels per channel. Consult docs/spec/hbm4_timing.adoc for our clean-room summary of tRCD/tRP/tRAS/tRFC; timing parameters are CSR-programmable. Fork structure from LiteDRAM's litedram/core/. Expose one AXI4 port per channel and one APB for CSRs. Refresh must support all-bank, same-bank, per-bank, and DRFM modes. Any deviation from LiteDRAM's bank-machine architecture must be justified in an ADR."), refresh_mgr ("Implement DRFM-capable refresh with PRAC counters. Defer refreshes during KV-cache write bursts and during long weight-streaming reads via a per-bank credit scheme documented in docs/arch/refresh_policy.md. Verify correctness via SymbiYosys property set fpv/refresh_liveness.sby proving no bank misses its tREFW window. Use the DREAM ISCA 2025 paper as the rowhammer-adversary benchmark."), addr_map ("Implement a programmable XOR hash address-mapping policy selectable per memory region via CSRs. Default policies: channel-striped for sequential (weight streaming), bank-interleaved for paged blocks (KV cache), row-stationary within a page for attention. Benchmark via traces from vLLM, FlashAttention-3, and SGLang provided in sim/traces/."), accel_core ("Instantiate 16 tiles, each containing one RedMulE systolic (FP16/FP8, 32×32 MACs), one SFPU (exp/log/softmax with 1:2 op-to-MAC ratio), five RISC-V baby cores based on CV32E40X, 1.5 MB L1 scratchpad with HCI-style streamers, and two NoC ports. Tile NoC is a 2D-mesh TileLink-C fabric. Per-tile programming model is reader/compute/writer like Tenstorrent tt-metal."), attention_engine ("Integrate the open FlashAttention HLS block from arXiv 2505.14314 per 8-tile cluster. Add PagedAttention scatter-gather via an AGCU-style address-generation unit. Verify against reference PyTorch FlashAttention-2 output."), mbist_wrapper ("Wrap every memory macro with IEEE 1500 and expose via IJTAG 1687. DFT gating under OpenTitan lifecycle TEST_UNLOCKED. BIST patterns: March-C+, TSV continuity."), ecc ("Implement SEC-DED link ECC plus a chipkill-class mode using Reed-Solomon across channel groups. The interaction with on-die DRAM ECC must be explicitly modeled; document the error taxonomy in docs/arch/ecc_stack.md."). Every prompt ends with "When done, open a PR that includes the module, testbench, Hjson register, Wavedrom timing diagrams in the doc, an ADR entry for any non-obvious choice, and a link to the SymbiYosys BMC trace on the protected branch."

5. IP licensing strategy
RTL (controllers, cores, NoC, digital PHY): Apache-2.0 with Developer Certificate of Origin on every commit (OpenTitan pattern). Analog/mixed-signal PHY, GDSII, layout: CERN-OHL-W-2.0 — weak reciprocity protects the PHY investment without forcing downstream SoCs to re-open. Verification IP and compatibility test vectors: Apache-2.0 with copyright assignment to the foundation via a CLA once the CIC is established (the RISC-V model: the tests are the moat). Firmware: Apache-2.0. Linux drivers: GPLv2 for upstream compatibility, dual-license where useful. Documentation: CC-BY-4.0 (never -SA; -SA fragments ecosystems). Trademarks: the project name and Netie Open HBM Compatible™ certification mark are strictly held by the Malaysian Sdn Bhd until Phase 3, then transferred to the foundation/CIC. Pure BSD/MIT is explicitly avoided for RTL because the lack of patent grant exposed the RISC-V ISA documents historically. CERN-OHL-S is avoided everywhere because strong reciprocity would kill hyperscaler adoption. Before any commercial silicon, all contributors sign an ICLA; individual DCOs alone do not meet the IP-vetting bar that silicon demands (this is the core insight behind lowRISC's "Silicon Commons" methodology — hardware bugs cannot be patched in the field).
Patent strategy. Join OIN 2.0 immediately under the free small-organisation tier; file defensive provisionals on the scheduler, the LPU microarchitecture, and any novel address-mapping heuristics purely for cross-license currency; avoid the Rambus FlexPhase/SureLink minefield by remaining strictly inside JEDEC JESD270-4A-standardized signalling and asserting FRAND defence; avoid the Google TPU and NVIDIA Tensor Core systolic-array claim territories by basing the LPU on the already-public-prior-art Tenstorrent Tensix pattern; publish early and aggressively on arXiv and in Hot Chips to invalidate future troll claims. Consider joining the China RISC-V Industry Alliance patent pool as a hedge if/when the project engages Chinese adopters.

10. Competitive landscape and existential threats, in one read
The window is roughly 24 months. NVIDIA Rubin ships H2 2026 with 288 GB HBM4 at 22 TB/s; Rubin Ultra in 2027; AMD MI455X in late 2026 with 432 GB HBM4 at 19.6 TB/s; Google TPU v8 on Samsung HBM4 through Broadcom in 2026; SK Hynix mass-producing 12-Hi HBM4 already, Samsung beginning in February 2026. The project will not outrun them on silicon. It can outrun them on openness: every one of those platforms is a proprietary stack with proprietary NVLink/UALink/ICI interconnect and NDA-only base dies.
The nearest philosophical competitor is Tenstorrent (Apache-2.0 TT-Metalium/TT-Forge, RISC-V Ascalon IP licensable, ~$1B raised, $9,999 open-source RISC-V AI workstation shipping) — the right move is partnering, because their deliberate HBM-avoidance using GDDR6+SRAM is exactly the missing integration surface an open HBM4 subsystem fills. Groq is neutralised by NVIDIA's ~$20B December-2025 licensing acquisition and is no longer an independent ecosystem. d-Matrix, Positron, MatX, Rain, Untether, Taalas, Axelera are all proprietary and small; they are not direct threats to an open-IP strategy. Chinese HBM (CXMT ~$4.2B IPO, targeting HBM3 end-2026 and HBM4 years later, YMTC hybrid-bonding partnership) is the second-most-important ally-of-convenience: they urgently need a non-US-beholden controller and will adopt an Apache-2.0 JEDEC-compliant reference if geopolitical caveats allow. SK Hynix, Samsung, Micron are potential customers, not competitors — a royalty-free controller saves them internal IP-NRE for the next base-die generation.
The existential risks worth internalising: CoWoS-L is 85% pre-booked through 2027 so real HBM4 silicon is gated regardless of IP; JEDEC JESD270-4A parametric tables (tRCD/tRP/tRAS/tRFC details) are behind free registration but not redistributable, forcing clean-room rederivation; no open PDK exists at N12FFC+/N5/N3 logic nodes that HBM4 base dies require; open SerDes IP at 8–13 Gb/s across 2048 lanes is a multi-year engineering effort beyond what any current open project has attempted; commercial Cadence/Synopsys HBM4 PHY IP licenses are rumoured in the low-single-digit-millions USD range per project and are not part of standard university programs.

11. Technical-risk register, ordered by severity
The highest-severity risks, beyond the already-catalogued packaging and PDK showstoppers, are: (5) HBM4 controller state-machine correctness across 64 pseudo-channel schedulers — the combinatorial state space defeats naive formal; compositional proof (one channel + non-interference lemma) is the only tractable path, and this is genuinely research territory. (5) ECC interaction across on-die + link + system layers at 16-high stacks, where whole-die failures become non-negligible and SEC-DED alone no longer suffices. (4) Refresh scheduling under LLM workloads where DRFM's 240–280 ns bank stalls destroy KV-cache decode tail latency (ISCA 2025 DREAM paper shows 12–49 % overhead in current designs) — this is the single most-valuable publishable-research contribution the project can make. (4) Address mapping policy where a single XOR scheme cannot be optimal for weight streaming + paged KV cache + dense attention simultaneously — requires programmable per-region mapping. (4) CDC correctness between HBM4 quarter-rate 2–3 GHz internal and accelerator 1–2 GHz clocks; open CDC tools are inadequate and commercial Jasper CDC or Questa CDC is effectively required for sign-off. (4) HBM4 PHY link training (WDQS-to-CK alignment, duty-cycle correction, per-lane deskew, VREF sweep) is complex, vendor-specific, and cannot be validated until silicon exists. (4) Rowhammer at 16-high stacks under GPU-class attack models published at USENIX Security 2025 — DRFM + PRAC tracker implementation correctness must be verified against directed adversarial fuzzing harness. (5) Silent data corruption at scale (TU Berlin April-2026 paper shows ECC misses transient logic errors in large-scale LLM training) is an emerging open problem that influences the required ECC strength. (3) Signal integrity at 2048 bits/8–13 Gb/s — crosstalk and simultaneous switching defeat standard layouts above 7.2 Gb/s (DesignCon 2025 study); requires 2.5D shielding and DFE/CTLE equalisation well beyond what openEMS or Xyce can sign off, forcing commercial Ansys HFSS or Cadence Clarity for any real PHY tapeout.

12. The strategic conclusion
The project's real thesis is not "build an HBM4 chip." It is "make HBM4 and LPU-style AI accelerators into a commodity rail, the way RISC-V commoditised the ISA." Silicon supremacy against NVIDIA Rubin and AMD MI400 is not achievable from Malaysia with one founder, a coding agent, and open infrastructure. Trademark-enforced JEDEC compatibility, coupled with a demonstrably-running reference implementation under Apache-2.0, is. The Phase-1 deliverable — a fully simulated, verified, Alveo-emulated HBM4 controller plus open LPU running real LLM inference — is achievable on a laptop and free HACC cluster access for under RM20k out of pocket if NLnet funds the primary founder year.
The window is narrow and the payoff asymmetric. NVIDIA Rubin Ultra lands in 2027; AMD MI500 in 2027; by 2028 the closed stacks are entrenched for another decade. If this project reaches v1.0 by end-2027 with live Malaysian, Singaporean, Chinese, Indian, and European adopters, it becomes the default open HBM4+LPU reference and the basis for a Linux-Foundation-hosted compatibility programme. If it does not, it becomes a useful set of RTL artefacts that accelerates someone else's attempt five years later. Both outcomes advance open hardware; the first changes the market. The decisive next action is the NLnet October 2026 application and the AMD HACC request, today.
