# sim/traces -- workload traces for trace-driven scoreboarding

The trace files in this directory are consumed by the addr_map regression
(`hw/ip/addr_map/dv/tests/test_traces.py`, forthcoming) and the eventual
hbm4_ctrl regression. Each trace is a small, copyright-clean
representation of a real workload's memory access pattern.

## Format

Plain ASCII, one event per line:

```
<cycle>  <op>  <system_address>  <length_bytes>  <region_hint>
```

- `cycle`           : monotonic uint64.
- `op`              : `R` | `W` | `A` (atomic) | `P` (prefetch).
- `system_address`  : hex `0x...`.
- `length_bytes`    : decimal.
- `region_hint`     : optional region index for the addr_map region table.

## Bundled traces

| File                  | Workload                          | Source                          |
| --------------------- | --------------------------------- | ------------------------------- |
| `vllm_decode.trc`     | vLLM 0.6 LLaMA-3 70B decode pass  | Synthetic, agent-generated 2026 |
| `flash_attn3.trc`     | FlashAttention-3 forward, 128h    | Synthetic, agent-generated 2026 |
| `sglang_prefill.trc`  | SGLang batch=8 prefill            | Synthetic, agent-generated 2026 |

The bundled traces are tiny synthetic stand-ins; full traces are
generated by `scripts/gen_traces.py` against unmodified upstream kernels
and are kept under `sim/traces/full/` (gitignored, regenerated on demand).

The synthetic versions are deterministic and deterministically-seeded so
the trace-driven regression is reproducible in CI.
